# x86_64 Ubuntuでのkartセットアップ

Ubuntu 24.04（amd64）＋NVIDIA GPUで、Isaac ROS 5.0 / ROS 2 Lyricalのkartコンテナを使う手順。
Jetson向けは[JetPackセットアップ](jetson.md)。ダウンロードしたインストーラshは使わずAPTで導入する。
repo管理の`dev.sh`・CLI更新スクリプトは利用する。

## 1. ホストの要件・基本依存

公式Isaac ROS 5.0のx86要件はUbuntu 24.04、Ampere以降のNVIDIA GPU（GPUメモリ8 GB以上）、
NVIDIA Driver 595以上、CUDA 13.2以上、空きディスク32 GB以上（2026-10-09参照）。
kartはRealSenseのソースビルドとmapping依存も含むため、キャッシュ・record分の余裕を確保する。
出典: [Isaac ROS 5.0 System Requirements](https://nvidia-isaac-ros.github.io/v/release-5.0/getting_started/index.html#system-requirements)。

第5節までのコマンドはUbuntuホストのBashで実行する。

```bash
uname -m                         # x86_64
cat /etc/os-release              # Ubuntu 24.04
nvidia-smi
df -h / /var/lib
locale                          # UTF-8
sudo apt update
sudo apt install -y software-properties-common ca-certificates curl gnupg git
sudo add-apt-repository -y universe
sudo apt update
sudo apt install -y vcstool python3-yaml build-essential dpkg-dev debhelper dh-python make \
  git-lfs usbutils
```

`nvidia-smi`が失敗する、またはDriver要件を満たさない場合は、
[Ubuntu公式NVIDIA driver手順](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/)で
要件を満たすGPU対応ドライバを選択・導入し、再起動後に再確認する。
`nvidia-smi`のCUDA表示はドライバの対応上限で、ホストのCUDA Toolkit導入済みを意味しない。
Docker経路ではCUDA Toolkit・TensorRT・ROSはコンテナに導入するため、ホストへ重ねて導入する必要はない。

`debhelper`は`debhelper-compat (= 13)`、`dh-python`は`dh-sequence-python3`を提供する。
ビルド依存不足時は上の基本依存を導入してから再ビルドし、`-d`で依存チェックを省略しない。
UTF-8設定とAPTロックへの対処は[Jetson版README](jetson.md)の該当節と共通。

## 2. Docker Engine

```bash
command -v docker || true
# Dockerが存在する場合だけ実行:
docker --version
sudo systemctl is-active docker
sudo docker version
```

Client・Serverが表示されれば既存導入を使い、インストールを省略する。
一般ユーザーのpermission deniedはグループ反映で解消するため、再導入の理由にしない。

### Docker未導入の場合のみ: 公式APT repositoryから導入

既存Dockerを更新・置換する手順ではない。`docker.io`等が導入済みなら重ねて導入せず、
既存Dockerの確認を先に行う。

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

出典: [Docker公式Ubuntu APT手順](https://docs.docker.com/engine/install/ubuntu/#install-using-the-apt-repository)。

## 3. NVIDIA Container Toolkit

```bash
command -v nvidia-ctk || true
```

未導入の場合だけ、production repositoryから導入する。experimentalは有効化しない。

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | \
  sudo gpg --dearmor --yes -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list > /dev/null
sudo apt update
sudo apt install -y nvidia-container-toolkit
```

既存導入・新規導入とも次で設定する。

```bash
sudo nvidia-ctk runtime configure --runtime=docker --set-as-default
sudo systemctl enable --now docker
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo usermod -aG docker "$USER"
newgrp docker
```

`newgrp`で入った新しいシェルで確認する。ログアウト・再ログインでもよい。

```bash
id -nG                          # dockerを含むこと
docker info --format '{{json .Runtimes}} {{.DefaultRuntime}}'
docker run --rm hello-world
docker run --rm --gpus all ubuntu:24.04 bash -lc 'echo "NVIDIA runtime OK"'
nvidia-ctk --version
```

最後のコンテナはGPU runtimeで起動できることの確認。CUDA計算成功の検証ではない。
出典: [NVIDIA Container Toolkit APT導入・設定](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)。

## 4. kart・CLI導入

`KART_REPO_URL`には実際のkart repository URLを指定する。配置済みならcloneを省略する。

```bash
mkdir -p ~/workspaces
read -r -p 'kart repository URL: ' KART_REPO_URL
git clone "$KART_REPO_URL" ~/workspaces/kart
cd ~/workspaces/kart
mkdir -p record map config
./scripts/update-isaac-ros-cli.sh && sudo isaac-ros init docker
isaac-ros status
```

更新スクリプトは`packages.repos`の固定commitを取得し、依存導入・debビルド・ホストへの導入を行う。
CLIに未commit変更がある場合は停止する。システムCLIをkart版へ置き換えるため、他プロジェクトにも影響する。
通常のcloneを使用する。worktree外のGit情報は単一mountから参照できない。
公式のホストIsaac ROS APT repository導入はローカルdebで代替し、ROS用APT設定はイメージ内で行う。

後日の更新:

```bash
cd ~/workspaces/kart
git pull --ff-only
./scripts/update-isaac-ros-cli.sh
```

## 5. センサー・初回コンテナ起動

RealSenseを接続する場合は[Jetson版のホストudevルール](jetson.md#realsenseのホスト側udevルール)を
同じくUbuntuホストへ適用して抜き差しする。未使用ならこの操作は不要。

```bash
cd ~/workspaces/kart
./scripts/dev.sh --build-local
```

Isaac ROS → RealSense → kartの順でビルドする。workspaceは`/workspaces/ros2_ws`、
ホストのkart全体は`/workspaces`にmountされる。jtopセットアップはx86_64では不要。
通常の入場は`./scripts/dev.sh`、別ターミナルは`docker exec -it kart_dev bash`。
イメージを再ビルドする際は実行中のROS・録画を終了し、ホストで`docker stop kart_dev`後に
`./scripts/dev.sh --build-local`を実行する。

## 6. コンテナ内の確認・ROSビルド

以降はkartコンテナ内で実行する。

```bash
cd /workspaces/ros2_ws
printenv ROS_DISTRO ISAAC_ROS_WS RMW_IMPLEMENTATION
# lyrical / /workspaces/ros2_ws / rmw_cyclonedds_cpp
nvidia-smi
ros2 pkg prefix isaac_ros_cuvslam
ros2 pkg prefix realsense2_camera
/usr/bin/python3 -c 'import tensorrt; print(tensorrt.__version__)'
/opt/inference/bin/python -c 'import onnx, onnxruntime'
/opt/env/bin/python -c 'import trajectory_planning_helpers, quadprog'
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install && source install/setup.bash
colcon test --packages-select kart_system kart_vehicle kart_joy
colcon test-result --verbose
```

`/opt/env`はamd64限定のRaceline環境。ROSノードはシステムPythonで起動し、仮想環境を自動activateしない。
パッケージ探索やimport成功はcuVSLAM・TensorRTのGPU実行成功とは別。

地図UIを使う場合:

```bash
cd /workspaces
./tools/app/start.sh
```

ブラウザで`http://127.0.0.1:8766`を開く。使い方は[Map Studio README](../../tools/app/README.md)。
vehicle/Joyの初回profile・起動は[Jetson版の第8節](jetson.md#8-dualsense接続初回profile)と共通。
x86_64でJoyを使用する場合は、コンテナへ`/dev/input`が見えることを確認し、
`dev.sh`は存在する`/dev/input`のマウントとinput/event所有GIDの補助グループを自動追加する。
設定反映はホストで`docker stop kart_dev`後に`./scripts/dev.sh`で再作成する。
車両USBを使う場合もデバイスパスと権限を確認する。
DDSはlocalhost限定なので、Jetsonとはrecord/mapの転送を利用する。
